# Навык `linear` — трекер портфеля

Linear — **единственный источник задач** портфеля и панель статусов: владелец смотрит
состояние с телефона, заводит задачи руками, спрашивает и отвечает. Команда — **DMI**,
задачи — `DMI-N`, проект задачи соответствует репозиторию, юниту или мета-слою.

Работаем **через официальное подключение Linear** своего раннера: коннектор/плагин Linear
или штатный Linear MCP. Сначала проверь доступные инструменты, включая поиск инструментов,
если раннер его предоставляет: коннектор может выдавать их под другим префиксом, отсутствие
именно `mcp__linear__…` не означает отсутствия доступа. Своих скриптов и синхронизации нет;
в git задачи не дублируются.

**Сессия Codex из Linear (`@Codex`).** Ответ в её агентском чате доставляет интеграция
Codex for Linear; для обычного финального ответа отдельный Linear MCP не требуется.
Отсутствие инструментов трекера не мешает ответить в текущем чате. Ответ в облачном чате
или успешный комментарий через MCP сами по себе не доказывают доставку результата
в агентский чат Linear — её проверяют отдельно. Не объясняй сбой этой доставки только
отсутствием MCP или ограничениями навыка.

- Шаблоны задачи, бага и вопроса владельцу — `references/templates.md`.

## 1. Старт сессии

Через доступное официальное подключение: свои задачи `In Progress` и задачи с меткой **«Ждёт владельца»**, у которых
последний комментарий — **не** агентский. Такой комментарий и есть ответ владельца к
применению (см. §4).

Инструменты Linear недоступны (не выданы средой, нет авторизации, сеть) — это не сбой сессии:
работаем по заданию из чата и отвечаем в нём; поля задач не меняем, отдельные комментарии
не публикуем. В отчёте укажи, какие действия с трекером выполнить не удалось, если они
требовались. Для сессии `@Codex` это не означает, что интеграция не доставит финальный ответ.

## 2. Завести задачу

Заголовок — одной строкой, глаголом: что будет сделано. Тело — по
`references/templates.md`. Проект — по репозиторию или юниту работы, приоритет `p1|p2|p3`,
`type: bug` — метка «Баг».

**Тариф Basic (с 2026-10-05): лимита на число задач нет.** Закрытые задачи не удаляются — их описание
и комментарии остаются историей работы; уборка — только автоархив (§5).

**Не заводи задачу на мелочь и служебное:** правку на несколько строк делай сразу в своей ветке,
пилоты, пробы и ход своей сессии в задачи не превращай. Задача — работа, которую сделают позже
или другим заходом, либо вопрос владельцу.

## 3. Вести задачу

- Взял в работу → `In Progress` + метка группы «Агент» (`Claude` или `Codex`) на себя.
- Каждый свой комментарий подписывать: **«🤖 Claude —»** или **«🤖 Codex —»**. Подпись —
  контракт: ответ владельца отличается от комментария агента ровно её отсутствием.
- Частичная работа: PR (заголовок и описание) и коммиты — `Part of DMI-N`;
  имя ветки — без `DMI-N`. Это связывает результат с задачей без её автозакрытия.
- Финальный PR, выполнивший все критерии задачи, — `Fixes DMI-N` (или `DMI-N` в имени
  ветки). Автозакрытие Linear остаётся включённым.
- После слияния перечитай статус и `stateHistory` задачи через Linear: частичный PR не
  должен переводить её в `Done`. Если перевёл — верни `In Progress`, объясни в комментарии
  и сообщи владельцу о расхождении интеграции.
- Итог работы по проекту — `project update` с `health` (`onTrack` / `atRisk` / `offTrack`),
  а не комментарий в задаче.
- **Закрыть проект.** Проект юнита или репозитория — постоянная панель: закрывается только со
  снятием юнита или репозитория (`Canceled`); `Completed` — лишь проекту с конечной целью, когда
  она достигнута. Через `save_project`, поле `state`. Зачем: задачи незакрытого проекта
  автоархив не берёт, даже `Done`, — они так и остаются в списках. Порядок: итоговый
  `project update` → открытые задачи проекта закрыть или перенести → статус проекта; после
  этого проект не трогать — любая правка откладывает автоархив.

## 4. Позвать владельца

Развилка прогона решается **вопросом в чате**. В Linear идут только долгосрочные решения —
те, что переживают сессию и нужны задаче бэклога.

Оформление: метка **«Ждёт владельца»**, исполнитель — владелец, связь **blocks** на задачу,
которая без ответа не движется, и комментарий по шаблону «решение владельца» (вопрос,
контекст, варианты, рекомендация, как ответить).

**Ответ пришёл:**
- ответ ясен → решение записать в описание задачи, снять метку «Ждёт владельца» и связь
  **blocks**, задачу — в работу; комментарий «🤖 Claude — применил: …»;
- ответ неясен → уточняющий комментарий, начинающийся **ровно** с «🤖 Claude — уточни:»
  («🤖 Codex — уточни:»). Метка и исполнитель-владелец остаются до нового ответа владельца.

## 5. Запреты

- **Не удалять** задачи, проекты, метки и статус-апдейты: закрытие — `Done`/`Canceled`,
  уборка — автоархив Linear (настройка команды, срок от месяца после закрытия; задачи
  открытого проекта — только после закрытия проекта, §3); удаление — только руками владельца.
- **Без секретов**: ключи, токены и пароли в задачи, описания и комментарии не пишутся.
- **Периметр PII.** Linear — внешний SaaS: имена, e-mail и телефоны клиентов в задачах не
  пишутся, только внутренние ID (KeyCRM и т. п.) и строки
  (политика PII репозитория, если она есть, — его `## Секреты` или `## Правила проекта`).
