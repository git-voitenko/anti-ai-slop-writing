# Шаблоны — задача, баг, решение владельца

Дополняет `SKILL.md`. Это тело задачи Linear (описание); поля — проект, приоритет, метки.

## 1. Задача

Заголовок — одной строкой, глаголом: что будет сделано.

```
**Цель:** одна фраза — зачем и что меняется
**Критерий приёмки:** проверяемо (тест/команда/grep); иначе — «уточнить у владельца»
**Срок/триггер:** дедлайн или событие
**Зависимости:** задачи/юниты/ADR или «нет»
**Ссылки:** ADR, changelog, PR
```

## 2. Баг

Метка «Баг» — задача едет даже с `p3`. Тело:

```
**Цель:** починить <что именно ломается>
**Что наблюдаем:** симптом одной строкой — вывод, код выхода, строка лога
**Как воспроизвести:** команда или последовательность шагов
**Ожидаемо / фактически:** одна строка на каждое
**Область:** файл/функция, если известна; иначе «не локализовано»
**Критерий приёмки:** тест, который краснеет до правки и зеленеет после
**Ссылки:** прогон, ревью, PR
```

Имена, e-mail и телефоны клиентов в баг не переносятся — только внутренний ID (KeyCRM и т. п.) и строка (Linear —
внешний SaaS; политика PII — в репозитории).

## 3. Решение владельца

Задаче — метка **«Ждёт владельца»**, исполнитель — владелец, связь **blocks** на
заблокированную задачу. Комментарий агента (подпись обязательна):

```
🤖 Claude — нужно решение владельца

**Вопрос:** что выбрать, одной фразой.
**Контекст:** 2–3 строки — почему развилка появилась и что уже сделано.
**Варианты:**
1. <вариант> — плюс: <…>; минус: <…>
2. <вариант> — плюс: <…>; минус: <…>
**Рекомендация:** <вариант N> — почему.
**Как ответить:** комментарием в этой задаче (без префикса «🤖»); можно одной строкой
«вариант N». Ответ увидит агент в начале следующей сессии.
**Что читать:** <файл/док/прогон>.
```
