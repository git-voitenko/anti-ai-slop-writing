## Ядро agent-kit · общий стандарт работы агентов

> Блок между маркерами `agent-kit:core` вставляет `agent-kit` (`bin/kit-sync.sh`); источник — `agent-kit/core/AGENTS.core.md`, здесь его не правят: `tools/kit-check.sh` сверяет копию с `.agent-kit.lock`. Правила репозитория — в проектном блоке ниже маркера `end`.

**Приоритет ядра.** Ядро главнее проектного блока. Проектный блок только добавляет ограничения и факты репозитория и не ослабляет инварианты ядра; конфликт — ошибка канона, PR с таким текстом не принимается (рубрика «Review guidelines»). Разрешённые разделы проектного блока — только заголовки уровня `##`: `## Проект`, `## Порядок чтения`, `## Проверки`, `## Выпуск`, `## Секреты`, `## Правила проекта`; любые другие `##` и текст вне этих разделов `kit-check` отвергает.

### Инварианты

1. **Репозиторий самодостаточен:** канон (`AGENTS.md` + роутер `CLAUDE.md`), реестр единиц (`INDEX.md`, где единиц несколько; иначе `README.md`), доки, проверки и навыки лежат в нём; для работы не нужны чужой репозиторий и файлы `~/…`.
2. **Именование — слагами** (латиница, `kebab-case`); конвенция и старые обозначения — `INDEX.md` или `README.md` репозитория.
3. **Один источник правды:** факт живёт в одном месте, остальные ссылаются. Общий стандарт — `agent-kit`: его копии здесь (managed-файлы из `.agent-kit.lock` и это ядро) меняются только `kit-sync`, не руками.
4. **Ничего не вытесняется молча:** мажорное снимается прибавлением — тег и `git mv` в `docs/archive/` (или `_archive/`) этого репозитория; исполненный план остаётся в `docs/plans/` с итогом. Снимок неизменяем.
5. **`main` меняется только merge PR.** Пишущая сессия — штатное дерево раннера, своя ветка от `origin/main`. Хуки `hooks/` (подключает `bash tools/hooks-install.sh`, идемпотентно) отказывают прямому коммиту в `main` основного checkout и push в `refs/heads/main` — это гигиена Mac; серверная защита — ruleset (режим A, шаг 7).
6. **Язык:** код — английский, доки и общение — русские (`docs/code-style.md` К9).
7. **Навыки — один источник** `.agents/skills/<имя>/SKILL.md` (корень навыков Codex); Claude видит их относительными симлинками `.claude/skills/<имя>` → `../../.agents/skills/<имя>`. Копий нет. Общие навыки `linear` и `verify` — managed; проектные — рядом, не managed.
8. **Задачи — Linear** через официальный коннектор/плагин Linear или штатный Linear MCP своего раннера (команда DMI; навык `linear`). Других трекеров и карточек в репозитории нет; ссылка из кода — `TODO(DMI-<n>)`.

### Как работаем

Один цикл на задачу. Шаги по порядку, детали раннера — в скобках; команды с пометкой «только Claude» у Codex отсутствуют.

1. **Дерево.** Claude — Desktop «worktree» или `claude -w <slug>`; Codex — режим Worktree или `codex --worktree`. Корень сессии = корень дерева.
2. **Свежая база.** В новом дереве, пока в нём нет своих коммитов: `git fetch origin`. Claude (`claude -w`, Desktop) — ветка уже создана, новую не заводить: `git merge --ff-only origin/main` (локальный `origin/main` мог отстать). Codex строит дерево от локальной ветки — ветка от `origin/main`; в detached HEAD — `git switch -c <slug> origin/main`.
3. **Правка и проверки.** `bash tools/verify.sh --fast` — один вход на репозиторий. Контракт: `0` — зелёный, `77` — SKIP (не хватает среды; причина в выводе), иначе — красный; первым шагом он вызывает `tools/kit-check.sh`. Claude делает это навыком `verify` перед коммитом.
4. **Коммит.** Обычный `git commit` в свою ветку, небольшими логическими порциями.
5. **Ревью до push.** Claude — `/code-review high origin/main...HEAD` (только Claude). Codex — субагент-ревьюер **только на чтение** по `git diff origin/main...<SHA>`, вручную — `/review` в режиме Detached. Правило — «Review guidelines» ниже. Это самопроверка автора; свидетельство ревью для merge даёт только шаг 7.
6. **Находки.** Подтверждённая находка о корректности или требованиях — чинить и коммитить; мелкая правка (несколько строк) — перечитать диф, существенная — полное ревью заново. Мелочь — стиль, имя, комментарий — чинить сразу. Каждая неисправленная — строкой в «Outcomes» плана (без плана — в описании PR) с пометкой: «ложная» — ревьюер ошибся; «по замыслу» — оставлено сознательно, риск — в ADR; «отложена» — настоящая, но вне корректности этой задачи или ждёт условия — пункт задачи Linear «Хвосты ревью <задача>» с триггером «когда чинить», номер — в той же строке.
7. **Посадка.** `git fetch origin` → `git merge origin/main` → `bash tools/verify.sh --fast` → `git push -u origin HEAD` → `gh pr create --base main --head <ветка> --fill` (тело: «Проверки: <команда> → <код>», «Ревью: <способ> → N, исправлено K», `Part of DMI-n` или `Fixes DMI-n`; плюс подпись раннера, если его правила её требуют) → PR отстаёт от `main` (strict) — `gh pr update-branch <n>`, затем снова verify → **независимое ревью финального SHA:** `review-gate <owner/repo> <n>` на Mac — ревьюер (Codex `gpt-6-astra` `xhigh` только на чтение по `git diff origin/main...<sha>` в чистом клоне или Claude `/code-review`) и check-run **`agent-review`** от App `dmi-labs-agent-reviewer` (ID 5370278) на точном `head.sha`; при P0/P1 — `failure`: чинить, push, снова `review-gate` → завершение по режиму репозитория (строка `Режим:` в `## Проект`, реестр — `agent-kit/REPOS.md`):
   - **режим A** (ruleset): `gh pr merge <n> --auto --merge` — GitHub сливает сам, когда `verify` и `agent-review` зелёные для текущего SHA;
   - **режим B** (без серверной защиты): `land <owner/repo> <n>` — проверяет `verify` и `agent-review` success для `head.sha`, `behind_by = 0`, `mergeable_state = clean` и сразу выполняет `gh pr merge --merge --match-head-commit <sha>`; иначе отказывает с причиной.

   `review-gate` и `land` — скрипты `bin/` локального клона `agent-kit` (путь — `agent-kit/REPOS.md`), в репозитории не копируются. Любой новый коммит после `review-gate`, включая `update-branch`, оставляет новый SHA без свидетельства — нужен новый `review-gate`. Строки «Проверки:» и «Ревью:» в теле PR — отчёт, не свидетельство. `<sha>` — литерал из отдельной `git rev-parse HEAD` (изоляция Claude режет `$(…)`). Конфликт — разрешить в своей ветке, повторить verify и ревью по шагу 6, запушить, `review-gate` по новому SHA.
8. **Основной checkout.** Git-хуки и ссылки раннеров читают основной checkout; навыки `.claude/skills/` — из своего дерева. Checkout подтягивает хук старта `tools/main-checkout-ff.sh`: у Claude — в `.claude/settings.json`, у Codex — одно глобальное определение в `~/.codex/hooks.json` (matcher `startup|resume`), которое вызывает копию текущего репозитория (`"$(git rev-parse --show-toplevel)/tools/main-checkout-ff.sh"`, если файл есть); проектная копия `.codex/hooks.json` не нужна. Codex доверяет определению хука по хэшу: правка `hooks.json` требует нового одобрения, правка `.sh` — нет. Хук: ff до `origin/main`, если checkout на `main` и чистый (так доезжают PR, слитые сервером); неудачный `fetch` повторяет раз, параллельный старт штатен. Иначе печатает JSON: `systemMessage` владельцу, `additionalContext` модели; checkout не трогает. Не прошёл `fetch` — проверить сеть и доступ к `origin`; сессия продолжает. Правку хука до слияния прогнать без `$CLAUDE_PROJECT_DIR` (так его зовёт Codex). Свежий `main` после посадки — Claude: `ExitWorktree` с `keep` (только Claude), `git pull --ff-only` в основном checkout, дальше — новым деревом (шаг 1).

### Облако

Клон отдельный (шаг 1), основного checkout нет — хук старта молчит, шаг 8 не нужен. Хуков в клоне может не быть — сначала `bash tools/hooks-install.sh`. Секретов в облаке нет (выпуски — только с Mac, `## Выпуск`). Установочные скрипты и стартовая инструкция — `docs/cloud/` репозитория (источник; в интерфейсы вставляет владелец).

**Облако PR не завершает.** Check-run `agent-review` публикует только `review-gate` на Mac, поэтому облачный PR всегда несёт в теле строку **`land: pending-local`**; завершает обслуживание 09:05 или локальная сессия: `review-gate` → режим A `gh pr merge --auto --merge`, режим B `land`. `merge_pull_request` из облака не вызывать: в режиме A его отвергнет ruleset, в режиме B это запрещено каноном.

- **Claude** (claude.ai/code, рутины). Работа — в ветке `claude/…`: интерактивной сессии её выдаёт среда (шаг 2 — как у `claude -w`), рутина стартует в detached HEAD — сначала `git switch -c claude/<slug>`; push — только в эту ветку. `gh pr …` не работает (прокси закрывает GraphQL; REST `gh api` работает) — PR через GitHub MCP `create_pull_request` или `gh api repos/<owner>/<repo>/pulls`, с маркером `land: pending-local`.
- **Codex, облако приложения.** Клон `/workspace/<repo>` на ветке `work` с `origin`, `gh` авторизован. До правок — `git switch -c codex/<slug>`: `work` одна у всех задач. Шаг 2 обязателен — контейнер кэшируется до 12 ч: `git fetch origin` → `git merge --ff-only origin/main`. PR создаёт сам, с маркером `land: pending-local`.
- **Codex, задачи из Linear и `codex cloud`** (legacy). Клон на ветке `work` без `origin`: `git fetch`, push и `gh` недоступны. База — срез на старте: до правок запомнить `git rev-parse HEAD`, дифф для ревью — `git diff <этот SHA>..HEAD`. PR — `make_pr` с маркером `land: pending-local` в описании; проверь URL GitHub, нет URL — вопрос владельцу. Завершает локальная сессия: `gh pr checkout <n>` в своём дереве → шаг 7.

### Codex

- **Вход:** Codex читает `AGENTS.md` корня и вложенные `AGENTS.md` подкаталогов по пути к правке; вложенный дополняет корневой и подчиняется правилу приоритета ядра.
- **Навыки:** discovery из `.agents/skills`; в начале работы убедись, что `linear` и `verify` видны.
- **База и дерево:** перед правками — `git fetch origin` и ff (шаг 2); worktree и ветка — от `origin/main`.
- **Ревьюер:** субагент только на чтение по `git diff origin/main...<SHA>` — дерево не правит, возвращает находки P0–P3.
- **Ограничения:** локально — полный цикл, включая `review-gate` и завершение; облако приложения — PR без завершения (`land: pending-local`); legacy — без `origin` и `gh`, PR только `make_pr`. `/goal` у Codex есть только интерактивно.

### Работа над задачей

- **План 5–15 шагов** — файл `docs/plans/<slug>.md` (путь уникален — иначе конфликт add/add), разделы Progress, Decision Log, Surprises, Outcomes; затем `/goal "все пункты <файл> выполнены, их проверки зелёные; не больше N ходов"` (Claude; у Codex — только интерактивно). Проверки должны попадать в вывод — оценщик видит только разговор. Сажать малыми порциями, каждую — через ревью и PR.
- **Продолжение работы** — задача Linear → план (адрес — в задаче) → `git log`/PR → `verify`. Решения владельца и процедуры — только в репозитории (план, `docs/adr.md`, канон); память раннера — предпочтения.
- **Массовая однотипная работа** (аудит, миграция сотен файлов) — Workflow у Claude, субагенты у Codex; под конкретную задачу, не по умолчанию.
- **Развилка владельца** — вопрос в чате. Автономная рутина вместо вопроса заводит задачу в Linear и останавливается.
- **Итог сессии и вопрос владельцу** — простым языком и по шагам: что сделано и зачем, что сделать владельцу (или «ничего») и зачем каждый шаг; термин — с расшифровкой. Непочиненные находки ревью (шаг 6) идут в итог так же просто; технические детали — в коммитах и PR.
- **Локальные ресурсы** (порты, имена compose-проектов, volumes, lock симулятора) именуются по дереву: десять сессий делят одну машину.
- **Повторилась ошибка** — предложить правку канона (проектного блока или PR в `agent-kit`), а не завести ещё одну проверку.

### Код-стиль

Выжимка для любого кода; канон и обоснования — `docs/code-style.md`, механика проверки — у репозитория (`## Проверки`).

- Комментарий — только «почему», ≤2 строки: суть + адрес дока (`data-mapping §6`, `Д-4`). Пересказ дока в коде запрещён (К1, К2).
- Факта нет в доках → сначала в док или задачу Linear, потом ссылка. Не наоборот.
- Шапка файла ≤3 строки: ответственность + точка входа + адрес спеки (К5).
- JSDoc — только у функций на границе модуля, однострочный; `@param` — лишь при неочевидной структуре (К6).
- Имя вместо комментария: магическое число → константа, условие → предикат (К7).
- Пометки только из словаря К8: `TODO(DMI-‹n›)` / `FIXME` / `NOTE` / `SECURITY`.
- Язык кода — английский: имена, комментарии, JSDoc, шапки, сообщения ассертов (К9). Языка не меняют пользовательский текст (письма, сообщения ботов, алерты, логи для владельца), документация, коммиты, общение. Старые комментарии задним числом не переводятся.
- Самопроверка: «почему»? → «уже в доке»? → «≤2 строк»? → «английский, если это код, а не текст для владельца»? Иначе — в док или в имя.

### Review guidelines

Ревью смотрит две вещи: **корректность** и **соответствие требованиям**.

- Находка — воспроизводимый сценарий: вход или состояние → неверный результат, падение, потеря данных, дыра в правах. Без сценария это не находка.
- Вкус, «можно красивее» и гипотетические будущие требования — не находки.
- Текст проектного блока, ослабляющий инвариант ядра, и правка managed-файла или `.agent-kit.lock` мимо `kit-sync` — находка P1.
- Код-стиль К1–К9 — §«Код-стиль» выше и `docs/code-style.md`; расхождение идёт строкой в отчёт, ревью им не краснеет.
- Подтверждённая находка о корректности или требованиях → чинить, коммитить, ревьюить заново. Остальное — по шагу 6: строкой в «Outcomes» плана, отложенное — в задачу Linear, и простым языком в итог владельцу.
- Рубрика P0–P3; в отчёт идут P0–P1, по ним `review-gate` публикует `failure`. Рискованный диф (необратимое, прод, деньги) — `/code-review max` (только Claude) или Codex `xhigh`.
- Ревьюер дерево не правит: читает диф и возвращает находки.

## Проект

`anti-ai-slop-writing` — навык редактирования текста и zero-dependency детектор шаблонных паттернов. Режим: A. Защита, проверки и история приёмки — `REPOS.md` agent-kit. Профиль agent-kit: node.

## Порядок чтения

1. `README.md` — назначение, использование и проверки.
2. `SKILL.md` и `references/` — правила навыка.
3. `docs/` — архитектура и разработка.

## Проверки

`bash tools/verify.sh [--fast]` — сначала `tools/kit-check.sh`, затем полный `npm run check` из корня репозитория: detector tests, skill validator, Codex plugin copy и self-scan. Fast и full выполняют один набор; контракт 0/77/1. CI `ci.yml` сохраняет Node 18/20/22.

## Выпуск

Пакет public; релизы публикуются из `main` после PR и обязательных проверок. Защита `main` — по режиму репозитория (строка «Режим:» в «## Проект»).

## Секреты

Проект не требует секретов для локальной проверки. Значения доступа не хранить в репозитории и не выводить.

## Правила проекта

- Сохранять совместимость Node 18, 20 и 22.
- `.codex-plugin/` и `skills/anti-ai-slop-writing/` синхронизируются скриптом `scripts/sync-codex-plugin.js`; не редактировать копию вручную.
- Сохранять проверки структуры skill, тесты detector и self-scan.
